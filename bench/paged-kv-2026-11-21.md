# Paged K/V: one pool, slots, prefix sharing (2026-11-21)

Plan of record: `docs/paged-kv.md` (the operator's ruling is at its top). Device pool only; the host pool, the CPU lane and YaRN are
not built. Box: RTX 4060 Ti 16 GB, rung 1 (Qwen3.6-35B-A3B UD-IQ3_XXS). Branch `feat/paged-kv`.

## 1. The design as built

| piece | where |
|---|---|
| `kv::PagePool`: page tables per slot, refcounts, copy on write, `share`, `fill`, `cut`, `room`; host only, `consistent()` for tests | `include/limbo/kvpool.hpp`, `src/kvpool.cpp` |
| the pool on the device: per full-attention layer the planes of `pool_pages` pages (page = 256 positions: K and Q8/Q4 rows at `page*256 + pos%256`, an f16 V page is `[kv head][256 dims][256 positions]`), zeroed at allocation; table upload through a pinned ring; copy on write = a device copy of one page | `src/cuda/gpu_kv.cu`, `src/cuda/gpu_pages.cu` |
| kernels read through the table: `attn_prep*`, `attn_part_*` (decode T = 1..8, verify windows), `attn_prep_rows*`, `kv_expand_window*`, and the tensor-core prompt attention (f16 pool read in place, one pass; Q8/Q4 dequantised into f16 windows as before). Null table = contiguous layout (the MTP block's own cache) | `src/cuda/attn_decode.cu`, `ops_rows.cu`, `dec_ops.hpp`, `ops.hpp` |
| slots replace homes: page table + recurrent state + captured graphs (decode and T-row sets are per slot); `set_slots`, `select_slot`, `slot_cut/reserve/share/room`, `release_slot`, `pool_stats` | `src/cuda/gpu_state.cu`, `include/limbo/cuda/gpu.hpp` |
| server: `--slots N` (default 1, `--sessions` alias), `GET /props`, `GET /slots`, `POST /slots/{id}?action=erase`, request field `id_slot`, `X-Limbo-Session` kept; prefix sharing between slots in both directions (the lender's newest checkpoint at or before the common prefix, or a snapshot of its live state when its whole tape is a prefix); 400 with numbers when the pool cannot hold a prompt, answers cut to what the pool has left | `src/serve.cpp`, `include/limbo/serve.hpp` |
| `--kv auto`: the most exact format whose pool covers `--ctx` positions in all slots (+ one page per slot) beside the MTP block, 2 checkpoint slots per slot, the reserve and a 160 MiB slack (a run without it lost the second slot to the block's graphs); if even q4 cannot, the pool is what fits and the start-up line says how many positions | `src/cuda/gpu_backend.cu` |

Deviation from the plan: the f16 prompt attention does not go through a gathered window. The tensor-core kernel takes the table and reads
the pool in place (template parameter `PAGED`): one pass, so it keeps the bits of the contiguous kernel at any length (windows
differ in the last bits at every window boundary, `tests/cuda_attn_test.cu`), and it saves the copy. Q8/Q4 keep the expansion.

Host-tier seams, unused: page ids from `pool.pages()` up are the host range; `PagePool::owner(slot, chunk)` is the per-chunk lane flag.

## 4. Open for the host tier

- `PagePool` ids >= `pages()` and the owner flag are free; `Gpu::pages_for` is the one place that takes pages before a write, and
  `page_copy` the one that copies, so a host page needs a mapped-pointer branch in the kernels and a lane split in `launch_*`.
- When the device pool is full the plan moves the coldest page to the host; today the server answers 400 (`Service::chat_completions`,
  `reserve` / `room`) and `--kv auto` says at start how many positions fit.
- Requests are still served one at a time (the HTTP layer runs one handler, `GET`s in between); `--slots N` gives N conversations in one pool,
  not N simultaneous decodes.
- Graphs are per slot: a new slot pays two eager passes per variant before its graphs capture (the load-time speculation calibration
  covers slot 0 only).
