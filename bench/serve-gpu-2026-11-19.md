# Serve on the GPU (2026-11-19)

`limbo_serve_gpu` is `limbo_serve` with the rung-1 forward pass on the RTX 4060 Ti: the same HTTP server, the same flags, the same
chat template, tool-call parser and tape (`bench/serve-2026-11-19.md`), but `limbo::cuda::Gpu` behind the `serve::Backend`
instead of the CPU reference. Everything below was run on 2026-11-19 on this machine (RTX 4060 Ti 16 GB, rung 1 =
Qwen3.6-35B-A3B UD-IQ3_XXS). The CPU reference answered the same first request at 0.67 prefill and 0.69 decode tok/s; the GPU
server answers it with 0.20 s of prefill and 0.10 s of decode (server timings).

Headline numbers, all quoted from the captures below:

| what | number |
|---|---|
| decode, temperature 0, 256 tokens, short prompt | **80.0 tok/s** (12.5 ms/token), server timings; 69.9 tok/s end to end including the 0.47 s prefill and HTTP |
| decode, temperature 0.7 + top_k 20 + top_p 0.95 / temperature 1.0 | 77.1 / 72.0 tok/s (the logits go to the host and the sampler runs there) |
| decode with context | 73.9 tok/s at 1.9k tokens, 65.8 tok/s at 3.7k (greedy, tool-call and answer turns) |
| prefill | 85.7 to 92.6 tok/s on the short prompts and the 1.9k one, 77.5 tok/s for the 1.6k tokens read at positions 2,075 to 3,698: one token per step, as the engine is today |
| agent turn 1, nothing cached | 1,906 prompt tokens (1,532 of system prompt) read in 22.25 s |
| the tape on a tool round | turn 2 of the agent exchange: `cached_tokens` 1,938 of 1,967, 29 tokens read in 0.36 s; turn 3: 2,075 of 3,698 |
| the tape on a new user turn | template default: **0** cached, 3,992 tokens re-read in 48.86 s; `preserve_thinking: true`: 3,977 of 4,004 cached, 27 tokens in 0.37 s |
| start-up | 14.2 s in the first window, 3.1 s in the second; 13.88 GB of VRAM at `--ctx 4096`, 13.97 GB at `--ctx 8192` |

## What was built

| file | what |
|---|---|
| `include/limbo/serve.hpp`, `src/serve.cpp` | `Backend` gained four hooks with correct defaults: `forward(token, pos, want_logits)`, `forward_greedy(token, pos)`, `prefill(tokens, n, pos0)` + `prefill_chunk()`, and `describe()`. The service reads the prompt with `prefill` in chunks (all but the last token, no logits, the client checked between chunks), then runs the last token through `forward_greedy` at temperature 0 or `forward` + `Sampler` above it. `Sampler::argmax` is the greedy rule (lowest id on a tie) the default `forward_greedy` and the sampler share. `RefBackend` implements `want_logits` (the CPU skips the head on prompt tokens now) and can own its `Ref`. The server's `main` moved into `serve::run_main(argc, argv, MainSpec)`, shared by both entries. |
| `tools/limbo_serve.cpp` | the CPU entry, now 22 lines over `run_main` (same flags, same output) |
| `include/limbo/cuda/backend.hpp`, `src/cuda/gpu_backend.cu` | `limbo::cuda::GpuBackend`: owns the `Model`, the `Gpu` and one pinned logits buffer. Prompt tokens: `Gpu::prefill(.., head_on_last = false)` in chunks of 64. `forward` = `step(head)` + `read_logits` into the pinned buffer. `forward_greedy` = `step(head)` + the device argmax, one int over PCIe. A failed launch throws; the server's existing handler resets the session and answers 500 (not exercised live). |
| `tools/limbo_serve_gpu.cu`, `mk/serve_gpu.mk` | the GPU entry (`--min-free-gb`, default 14.6, is its one extra flag; `--threads` is accepted and ignored) and its build rule; `make serve-gpu` or `make tools` builds it |
| `tests/serve_test.cpp` | extended: the fake backend counts the new hooks |

`GpuBackend::open` fails with the engine's own message; the entry exits 3:


## Commands

```
nice -n 10 make -j6 BUILD=build-gpuserve tools build-gpuserve/bin/tests/serve_test
build-gpuserve/bin/tests/serve_test
flock -w 7200 build/gpu.lock build/tmp/gpuserve/smoke.sh     # the server for the whole window; the script starts it, runs the requests, kills it by PID
```

`smoke.sh` starts `build-gpuserve/bin/tools/limbo_serve_gpu -m $M --host 127.0.0.1 --port 18091 --ctx 4096 --model-name qwen3.6-35b-a3b`
and kills exactly the PID `$!` gave it. `$M` is the rung-1 file named in the task. Scratch (requests, the system prompt, the
scripts, every raw response) is under `build/tmp/gpuserve/`.

## Tests

`serve_test` with the fake backend: 99 `ok` lines, no `FAIL`, in 11 consecutive runs. New checks (all in the "backend hooks" block, the
"Backend default" block and the tape block): at temperature 0 every prompt token but the last goes through `forward(.., false)`
and the last one plus every generated token come back through `forward_greedy` (`n_greedy == generated tokens`); at temperature
above 0 `forward_greedy` is never called and the prompt still skips the head; with `prefill_chunk() == 7` the backend gets
`ceil((prompt - 1) / 7)` calls, none longer than 7 tokens, at consecutive positions; a backend that implements only `forward(token, pos)`
still serves (defaults: `nullptr` when skipped, argmax with the lowest id on a tie, per-token prefill); a continued tape skips the head
on exactly the new prompt tokens but the last.

## Open

- **Prompt reading is the slow part.** Prefill is one token per step: 1,906 tokens take 22 s, a full 3,992-token re-read 49 s. `Gpu::prefill` exists in
  the working tree (from the other agent) but is a loop over `step()`; the backend already hands it 64-token chunks and skips the head, so a batched
  implementation needs no server change. Numbers above are for the loop.
- **Decode slows with context** in the PoC kernels: 80 tok/s on a 43-token prompt, 74 at 1.9k, 66 at 3.7k.
- **The template default re-reads the whole prompt on every new user turn** (48.86 s at 4k tokens). A harness should send
  `chat_template_kwargs: {"preserve_thinking": true}` or the server needs a policy; this is the operator's call and the server still does not change the
  template. Repeating a request, or a prompt shorter than the tape, also re-reads (nothing is rewound).
- **Sampling above temperature 0 is on the host**: 1 MB of logits per token and a CPU sampler, 72 to 77 tok/s against 80. A device sampler would
  close it.
- One session, one tape: a second conversation (the sidekick) evicts the first. Completions run one at a time. `Gpu::open` limits `--ctx` (read in
  `src/cuda/gpu.cu`: 8192; 4096 and 8192 were run here).
- `--threads` does nothing in the GPU entry. `mk/README.md` does not list `serve_gpu.mk` yet (not my file).
